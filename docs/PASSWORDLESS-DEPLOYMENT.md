# Tracklistify Passwordless Deployment Guide

## Overview

The deployment script (`infra/deploy.sh`) implements a complete end-to-end passwordless deployment for Tracklistify using Azure Managed Identity and Entra ID authentication for all Azure services.

## Prerequisites

### Required Environment Variables

```bash
export ACR_ACCESS_KEY="your-acrcloud-access-key"
export ACR_ACCESS_SECRET="your-acrcloud-access-secret"
```

### Optional Environment Variables

```bash
export ENVIRONMENT_NAME="tracklistify"        # Default: tracklistify
export LOCATION="uksouth"                     # Default: uksouth
export DB_ADMIN_LOGIN="tracklistifyadmin"     # Default: tracklistifyadmin
export DB_ADMIN_PASSWORD="<random>"           # Auto-generated if not provided
export ACR_HOST="identify-eu-west-1.acrcloud.com"  # Default ACRCloud host
```

## Architecture

### Passwordless Authentication Flow

1. **PostgreSQL**: Uses Entra ID authentication
   - Logged-in user is set as Entra ID admin
   - Container apps authenticate using their managed identities
   - No database passwords in environment variables

2. **Azure Storage**: Uses Managed Identity
   - Container apps have "Storage Blob Data Contributor" role
   - Authenticate via DefaultAzureCredential
   - No storage keys in environment variables

3. **Azure Key Vault**: Uses RBAC
   - Container apps have "Key Vault Secrets User" role
   - ACRCloud credentials stored securely in Key Vault
   - Access via managed identity

4. **Redis**: Currently uses access keys (fallback)
   - Future: Can be upgraded to Entra ID when available

## Deployment Steps

The script executes 14 steps:

1. **Get logged-in user info** - Retrieves Entra ID object ID and display name
2. **Create resource group** - Creates or reuses existing resource group
3. **Deploy Container Apps Environment** - Sets up the managed environment and Log Analytics
4. **Deploy PostgreSQL with Entra ID** - Enables Entra ID authentication and sets admin
5. **Deploy Redis** - Creates Redis cache instance
6. **Deploy Storage** - Creates blob storage account
7. **Deploy Key Vault** - Stores ACRCloud secrets securely
8. **Create ACR** - Sets up Azure Container Registry (idempotent)
9. **Build backend image** - Builds and pushes backend Docker image
10. **Deploy containers** - Deploys backend, celery, and frontend containers with passwordless config
11. **Assign RBAC roles** - Grants permissions to managed identities
    - Storage Blob Data Contributor (backend + celery → storage)
    - Key Vault Secrets User (backend + celery → Key Vault)
12. **Build frontend image** - Builds and pushes frontend with backend URLs
13. **Update frontend** - Updates frontend container app with new image
14. **Output summary** - Displays all deployment information

### Code Changes Required

Your application code needs to be updated to use passwordless authentication:

#### PostgreSQL Connection (psycopg3)

```python
from azure.identity import DefaultAzureCredential
import psycopg
import os

def get_postgres_connection():
    host = os.environ['POSTGRES_HOST']
    database = os.environ['POSTGRES_DATABASE']
    
    # Get Entra ID token
    credential = DefaultAzureCredential()
    token = credential.get_token("https://ossrdbms-aad.database.windows.net/.default")
    
    conn = psycopg.connect(
        host=host,
        dbname=database,
        user="<app-name>@<hostname>",  # Managed identity name
        password=token.token,
        sslmode="require"
    )
    return conn
```

#### Azure Storage (Blob)

```python
from azure.identity import DefaultAzureCredential
from azure.storage.blob import BlobServiceClient
import os

def get_blob_service_client():
    account_name = os.environ['STORAGE_ACCOUNT_NAME']
    account_url = f"https://{account_name}.blob.core.windows.net"
    
    credential = DefaultAzureCredential()
    return BlobServiceClient(account_url, credential=credential)
```

#### Azure Key Vault

```python
from azure.identity import DefaultAzureCredential
from azure.keyvault.secrets import SecretClient
import os

def get_acrcloud_credentials():
    vault_uri = os.environ['KEY_VAULT_URI']
    
    credential = DefaultAzureCredential()
    client = SecretClient(vault_url=vault_uri, credential=credential)
    
    access_key = client.get_secret("acr-access-key").value
    access_secret = client.get_secret("acr-access-secret").value
    
    return access_key, access_secret
```

## Security Benefits

1. **No secrets in environment variables** - Database passwords, storage keys, etc. are not exposed
2. **Automatic credential rotation** - Managed identities don't require manual rotation
3. **Audit trail** - All access is logged via Azure Activity Log
4. **Least privilege** - Each service only has the permissions it needs
5. **Centralized secret management** - ACRCloud credentials in Key Vault

## Idempotency

The script is safe to re-run:

- Resource creation uses `|| true` or checks for existing resources
- Role assignments ignore "already assigned" errors
- ACR creation is idempotent
- Image builds can be re-run without issues

## Troubleshooting

### Permission Issues

If you see permission errors, ensure:

1. You're logged in with `az login`
2. Your account has sufficient permissions to create resources
3. You have permission to assign Entra ID admin roles on PostgreSQL

### ACR Build Failures

If Docker builds fail:

1. Check that Dockerfiles exist in `backend/` and `frontend/`
2. Ensure you're running from the project root directory
3. Verify Azure CLI has permissions to use ACR

### Role Assignment Delays

RBAC role assignments can take a few minutes to propagate. If containers can't access resources immediately:

1. Wait 2-3 minutes
2. Restart the container apps: `az containerapp restart ...`
